# Smart Showcase

Личный кабинет продавца с AI-ассистентом для улучшения объявлений — что-то вроде упрощённого кабинета продавца на Авито.

**Что делает:** продавец видит список своих объявлений (авто, недвижимость, электроника), может открывать, редактировать их и понимать, какие из них «недозаполнены» и требуют доработки. Для каждого объявления AI-ассистент (Groq / Llama 3.3) помогает написать продающее описание и оценить рыночную цену.

**Для кого:** частные продавцы и небольшие магазины, которым нужно быстро приводить объявления в порядок, не придумывая текст и цену с нуля.

**Основные фичи:**
- Список объявлений с поиском, фильтрами по категории, сортировкой и пагинацией
- Фильтр «только требующие доработок» — подсвечивает объявления с пустым описанием или незаполненными характеристиками
- Редактирование с динамическими полями под каждую категорию, валидацией и автосохранением черновика в localStorage
- AI-генерация описания и анализ цены прямо из карточки редактирования
- Разные типы товаров (авто / недвижимость / электроника) со своим набором характеристик

## Стек технологий

**Клиент:**
- React 19 + TypeScript
- Vite
- react-router-dom v7
- SCSS Modules
- Кастомные хуки вместо react-query (`useFetch`, `useDebounce`, `useLocalStorage`, `useAI`)
- Нативный `fetch` с `AbortController`

**Сервер:**
- Node.js + Express + TypeScript
- ts-node-dev
- PostgreSQL (драйвер `pg`, без ORM)
- Groq API (llama-3.3-70b-versatile) для AI функций

**Инфраструктура:**
- Docker + docker compose (Postgres + приложение)
- В продакшене Express раздаёт собранный клиент и API с одного origin

## Запуск через Docker (рекомендуется)

Поднимает Postgres и приложение (API + собранный клиент) одной командой.

### Требования
- Docker + docker compose
- Ключ Groq: [console.groq.com/keys](https://console.groq.com/keys) → Create API Key

```bash
cp .env.example .env   # пропиши GROQ_API_KEY
docker compose up --build
```

Приложение будет на `http://localhost:3001` (клиент и API на одном origin).
При первом запуске схема создаётся автоматически, а БД наполняется из `server/src/db.json`.
Данные хранятся в Docker-томе `pgdata` и переживают перезапуск контейнеров.

## Деплой (Render + Neon)

Приложение собирается из `Dockerfile` на Render, БД — бесплатный Postgres на Neon.

1. **Neon:** создай проект на [neon.tech](https://neon.tech) и скопируй connection string
   (вида `postgresql://user:pass@ep-xxx.neon.tech/neondb?sslmode=require`).
2. **Render:** Dashboard → New → Blueprint → выбери этот репозиторий (подхватится `render.yaml`).
3. Заполни переменные: `DATABASE_URL` — строка из Neon, `GROQ_API_KEY` — ключ Groq.
4. После деплоя таблица создастся и наполнится автоматически. Проверка: `https://<сервис>.onrender.com/api/health`.

Без `GROQ_API_KEY` приложение работает, AI-эндпоинты отвечают 503.
На бесплатном плане Render сервис засыпает после 15 минут простоя — первый запрос после этого идёт ~30–60 секунд.

## Локальная разработка (без Docker)

### Требования
- Node.js v20+
- Запущенный PostgreSQL (можно поднять только БД: `docker compose up db`)
- Аккаунт на [console.groq.com](https://console.groq.com) для AI функций

### 1. Клонируй репозиторий

```bash
git clone https://github.com/твой-username/smart-showcase.git
cd smart-showcase
```

### 2. Настройка сервера

```bash
cd server
npm install
cp .env.example .env   # пропиши GROQ_API_KEY и DATABASE_URL
```

`server/.env`:

```
PORT=3001
GROQ_API_KEY=твой_ключ_от_groq
DATABASE_URL=postgres://shop:shop@localhost:5432/shop
CLIENT_URL=http://localhost:5173
```

Получить ключ Groq: зайди на [console.groq.com/keys](https://console.groq.com/keys) → Create API Key.

Запусти сервер:

```bash
npm run dev
```

Сервер запустится на `http://localhost:3001` и при старте создаст/наполнит таблицу.

### 3. Настройка клиента

```bash
cd ../client
npm install
npm run dev
```

Клиент запустится на `http://localhost:5173`

## API эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/items` | Список объявлений с фильтрами, поиском, сортировкой, пагинацией |
| GET | `/items/:id` | Одно объявление |
| PUT | `/items/:id` | Обновление объявления |
| POST | `/ai/suggest-description` | Генерация описания через AI |
| POST | `/ai/suggest-price` | Анализ рыночной цены через AI |

### Параметры GET /items

| Параметр | Тип | Описание |
|----------|-----|----------|
| `q` | string | Поиск по названию |
| `limit` | number | Количество на странице |
| `skip` | number | Пропустить N записей |
| `categories` | string | Категории через запятую: `auto,electronics` |
| `needsRevision` | boolean | Только требующие доработок |
| `sortColumn` | string | Поле сортировки: `title` или `createdAt` |
| `sortDirection` | string | Направление: `asc` или `desc` |

## Функциональность

- **Список объявлений** — поиск, фильтры по категории, переключатель "Только требующие доработок", сортировка, пагинация с окном из 5 страниц
- **Просмотр объявления** — все характеристики, блок незаполненных полей
- **Редактирование** — динамические поля в зависимости от категории, валидация обязательных полей, сохранение черновика в localStorage, toast уведомления
- **AI ассистент** — генерация описания и анализ рыночной цены через Groq API, результат в тултипе с кнопками "Применить" и "Закрыть"

## Принятые решения

**Без внешних библиотек для стейта и запросов** — вместо Redux и React Query написаны кастомные хуки. Это позволило лучше понять как работают эти инструменты внутри.

**PostgreSQL без ORM** — используется драйвер `pg` и обычный SQL. Схема создаётся при старте, а первичные данные берутся из `db.json` (сид только если таблица пустая). Фильтр `needsRevision` вычисляется в коде, так как зависит от заполненности полей `params`.

**Один origin в продакшене** — Express раздаёт собранный клиент и API (`/api/*`) с одного адреса, поэтому CORS и прокси не нужны. В dev-режиме клиент на Vite проксирует `/api/*` на сервер. Ключ Groq API хранится только на сервере и никогда не попадает на клиент.

**Docker** — `docker compose` поднимает Postgres и приложение; данные лежат в томе `pgdata` и переживают перезапуск.

**Черновик в localStorage** — при обновлении страницы форма восстанавливается. Черновик удаляется после сохранения или отмены.

**AbortController** — при переходе между страницами незавершённые запросы отменяются чтобы избежать обновления размонтированных компонентов.
